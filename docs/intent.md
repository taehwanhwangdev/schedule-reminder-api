# Intent

## 목적

일정을 등록하면 정해진 시점에 알림을 보내는 서버리스 API를 만든다.
기능은 단순하게 두고, 알림 시스템에서 흔한 실패(누락, 중복 발송, 시간대 오류)를 설계와 테스트로 다루는 데 집중한다.
AI 코딩 도구(Claude Code)로 개발하되, 결과물은 테스트와 직접 리뷰로 검증한다.

## 사용자·문제

- 사용자: 일정을 API로 등록하고 미리 알림을 보내야 하는 서비스(예: 예약·수업·모임 서비스의 리마인더)
- 문제
  - 누락: 스케줄러 지연이나 인덱스 반영 지연으로 알림이 빠진다
  - 중복: 스케줄러가 겹쳐 실행되거나 같은 호출이 두 번 들어오면 같은 알림이 두 번 간다
  - 시간대: 현지 시각과 UTC 변환, DST 전환 때문에 알림 시각이 틀어진다
  - 경합: 발송 직전에 일정이 삭제돼도 알림이 나간다

## 범위

- 일정 등록·조회·삭제 API (시간은 UTC 저장, 시간대는 IANA 이름, 알림 시점은 목록)
- 스케줄러: 주기 실행 → 시간 창 조회 → 발송 전 선점 → 발송 → 완료 표시, 건별 실패 처리
- 발송 채널 1개 (spec에서 결정)
- 단위·통합 테스트, AWS 배포
- 작업 방식: intent → spec → plan → CLAUDE.md·Hook·Skill → review → 배포, 작업 로그(docs/ai-log.md)

## 범위 밖

- 화면(웹·앱), SMS, 다중 채널, 인증, 대규모 트래픽 최적화
- 정확히 1회 발송 보장: 외부 발송과 DB 갱신을 하나로 묶을 수 없으므로 목표로 하지 않는다
- 실제 개인 정보: 저장소와 테스트에는 샘플 데이터만 쓴다
